# Digest — дайджест проекта Grafikus (v8.1.1)

Короткая сводка для быстрого входа в контекст (люди и AI-ассистенты).

## Суть

- Настольное приложение (CustomTkinter) для сборки сводного графика
  дежурств врачей стационара.
- Вход: файлы отделений `.xlsx/.xls/.csv/.pdf/.txt` в одной папке.
- Выход: Word (3 колонки) + TXT (проверка) + Excel (аудит).
- Один входной файл = одно отделение (кроме многостраничного Excel).
- Портативность: справочники и `icon.ico` рядом с exe.

## Ключевые сущности

- `(doctor, dept_name)` — ключ дежурства; значение — нормализованное время
  (`16-09`, `09:00-18:00`) или буква смены (`А`/`Р`/`Э`) + время.
- `DEPT_ABBR` — сокращения отделений (АДМ, ОТВ, ПО, ОАР, ХИР, ГН ХИР,
  ГИН, УРО, ТРАВМ, ТР П, ЛАБ, НЕВР, РЕНТ, МХГ, ТЕР).
- `DEPARTMENT_ORDER` — порядок сортировки отделений; `'АДМ'` первым.
- `all_data[day][(doctor, dept)]` — собранные дежурства.
- `doctors_by_dept[dept]` — список врачей по отделениям.

## Парсеры

- `administration` — администрация: `Дата, день недели` + площадки в
  шапке; значения в `datetime`; запись `''` (без времени).
- `standard` — обычный Excel/CSV отделений; `Дежурный врач` в шапке.
- `oar` — ОАР: буквы А/Р/Э **перед** временем; время из предпоследней строки.
- `surgery` — хирургия: PDF через `extract_tables`; TXT через построчный парс.
- `multisheet` — многостраничный Excel (Володарского): листы по месяцам,
  отделения внутри листа, известные врачи (Кодиров).

## Правила

- Месяц и год в файле должны совпадать с выбранными — иначе файл в список
  исключённых, данные не подмешиваются.
- Время нормализуется `core.utils.normalize_time`: `9\8 → 09-08`,
  `9/8 → 09-08`, `9-8 → 09-08`, `09:00-18:00 → 09:00-18:00`.
- Имена врачей фильтруются `core.doctor_validator.is_valid_doctor_name`
  (защита от «Код», «ФИО», «Дата» и др. заголовков).
- Первая страница Word: ≤ 48 строк; остальные: ≤ 59 строк.
- **Администрация** выводится без времени: `ФИО (АДМ)`, в TXT —
  `* ФИО (АДМ)`, в Word — жирным, первой строкой после даты.

## Где что лежит

- `main.py` — точка входа; `ui/app.py` — интерфейс.
- `core/` — конфиг, утилиты, валидатор, оркестратор (`schedule_builder`).
- `parsers/` — модульные парсеры (administration, standard, oar, surgery,
  multisheet, base).
- `output/` — генераторы результата (word_builder, txt_builder).
- `service/docs/` — генераторы документации и упаковки для ИИ.
- `service/run.py` — запускатель служебных скриптов.
- `project_info/manuals/` — USER_MANUAL.md + .docx + .pdf.
- `assets/` — `project_logo.png/.ico` (или корневой `icon.ico`).
- `data/` — тестовые данные (вне git).

## Границы (что делаем и не делаем)

- НЕ храним ФИО пациентов в репозитории: `data/` в `.gitignore`.
- НЕ ломаем модульную структуру: новый парсер — в `parsers/`, не в `main.py`.
- НЕ правим сгенерированные документы вручную — только через make_docs.py.
- НЕ удаляем `is_valid_doctor_name` без причины — там защита «Кодирова».
