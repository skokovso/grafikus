# ARCHITECTURE — Сводный график дежурств

## 1. Цель
Автоматизация сбора разрозненных графиков дежурств (Excel, CSV, PDF) в единый стандартизированный документ Word для утверждения главным врачом.

## 2. Слои и файлы
- **`main.py`**: Точка входа. Инициализирует `ui/app.py`.
- **`ui/app.py`**: Графический интерфейс (CustomTkinter). Отвечает только за отображение и вызов `schedule_builder`.
- **`core/`**: Ядро.
  - `config.py`: Константы, сокращения отделений (ОТВ, ПО, ХИР и т.д.).
  - `utils.py`: Утилиты (`normalize_time`, `extract_day`, `find_month_in_text`).
  - `doctor_validator.py`: Строгая валидация имен (отсеивает заголовки, но сохраняет сложные фамилии).
  - `schedule_builder.py`: Оркестратор. Сканирует папку, определяет тип файла, вызывает нужный парсер, агрегирует данные и отдает их в `output`.
- **`parsers/`**: Модули чтения.
  - `standard.py`: Обычные Excel-файлы отделений.
  - `oar.py`: Специфичный парсер ОАР (читает буквы А/Р/Э и время из предпоследней строки).
  - `surgery.py`: Парсер хирургии. Использует `pdfplumber.extract_tables()` для корректной обработки сдвоенных ячеек, где дата и имя могут быть разнесены.
  - `multisheet.py`: Парсер для файлов типа 'Володарского' с листами по месяцам.
- **`output/`**: Модули записи.
  - `word_builder.py`: Формирование 3-колоночного Word-документа с шапкой.
  - `txt_builder.py`: Быстрый текстовый дамп для проверки.
  - `excel_builder.py`: Плоская таблица Excel для удобной фильтрации и аудита данных.

## 3. Потоки данных
1. Пользователь выбирает папку в UI.
2. `schedule_builder` находит все `.xlsx`, `.pdf`, `.txt` (исключая 'сводный').
3. Для каждого файла `detect_department` определяет отделение.
4. Вызывается соответствующий парсер → возвращает `dict[day, dict[(doctor, dept), time]]`.
5. Данные проверяются на соответствие выбранному месяцу/году.
6. `word_builder` распределяет блоки по страницам (48 строк на 1-й странице, 59 на остальных).
7. Файлы сохраняются в `<input_folder>/Сводный график/`.

## 4. Безопасность
- Входные файлы с реальными данными хранятся в `data/`, который добавлен в `.gitignore`.
- Парсинг PDF происходит локально, данные никуда не отправляются.
- Нет сетевых запросов в коде.
